# Contributing

Thanks for your interest in improving Uptime Monitor Service.

## Before you start

- Search existing issues before opening a new one.
- For large changes, open an issue first to discuss the design.
- Never include credentials, private URLs, customer data, databases, logs, or screenshots containing sensitive information.

## Pull request guidelines

1. Keep changes focused and explain the motivation.
2. Update documentation and `.env.example` when configuration changes.
3. Run relevant syntax checks and manual tests; describe what was and was not tested.
4. Avoid committing generated files, local databases, and deployment secrets.
5. Use a clear commit message, for example `fix: handle monitor timeout consistently`.
